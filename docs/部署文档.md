## 二、部署前提

| 依赖 | 要求 | 检查命令 |
| --- | --- | --- |
| Docker Desktop | 已启动 | `docker ps` |
| Ollama | 已运行，已拉取 `qwen2.5:1.5b` 与 `quentinz/bge-large-zh-v1.5:latest` | `ollama list` |
| my-rerank 容器 | 运行于宿主机 9999 端口（BAAI/bge-reranker-v2-m3） | `curl http://localhost:9999/rerank ...` |

> 说明：Ollama 与 my-rerank 为宿主机服务，容器内通过 `host.docker.internal` 访问（compose 已配置 `host-gateway`，Docker Desktop 自动生效）。

## 三、一键部署

## 六、常用运维命令

```powershell
cd d:\ai\ai_legal\ZhiFaTong

docker compose ps                    # 服务状态
docker compose logs -f backend       # 跟踪后端日志
docker compose restart backend       # 重启单个服务
docker compose up -d --build frontend  # 代码更新后重建前端
docker compose down                  # 停止全部服务（保留数据卷）
docker compose down -v               # 停止并清空数据（慎用：将丢失知识库与向量索引）
```

> 首次启动时，后端会自动完成：账号种子写入 → 法律知识库种子入库（36 篇法条/案例/司法解释）→ 向量索引构建 → MCP 工具注册。清空数据卷后重启将自动重建。

## 八、常见问题（FAQ）

| 现象 | 原因与处理 |
| --- | --- |
| 问答/审查响应缓慢 | 宿主机 Ollama 未使用 GPU 或首次模型加载中；确认 `ollama list` 模型存在，等待 1~2 分钟预热后重试 |
| 后端启动报 MySQL 连接失败 | MySQL 仍在初始化；compose 已配置 depends_on + healthcheck，如仍失败执行 `docker compose restart backend` |
| SSE 无流式效果（一次性输出） | 代理层缓冲导致；本项目 nginx.conf 已设置 `proxy_buffering off`，若自行修改代理需保留该配置 |
| 前端容器 unhealthy | 健康检查使用 IPv4 环回地址（127.0.0.1），如自定义镜像需保留此设置 |
| 端口冲突 | 修改 compose 文件中 8188 / 28000 / 13306 / 26379 / 7474 映射后 `docker compose up -d` |
| Windows PowerShell 脚本执行策略报错 | 仅影响本地测试脚本执行提示，不影响 Docker 部署 |
