## 一、项目概述

### 1.1 项目定位

**智法通（ZhiFaTong）** 是一套面向企业与律所的**企业级智能法律顾问平台**，以本地化大模型（Ollama + Qwen）为推理底座，围绕法律场景构建了两大核心能力：

1. **智能法律问答（Legal RAG）**：基于"三路混合检索 + Cross-Encoder(Rerank) 精排 + Self-RAG 自评估"的检索增强生成链路，回答**引用真实法条**、标注**置信度**，并支持 **SSE 逐字流式输出**；
2. **多 Agent 对抗式合同审查**：以状态图引擎编排"条款拆分 → 法务/合规/业务三视角独立推理 → 主审风险识别 → 复核遗漏检查 → 反方辩论 → 仲裁裁决 → 风险评分 → 修改建议"，输出结构化审查报告与**带修改痕迹的 AI 修订版合同**。

平台采用**全容器化部署**（Docker Compose 一键拉起 MySQL / Redis / Neo4j / 后端 / 前端五服务），支持**多用户并发**与**角色分层数据范围**管理，开箱即用。

### 1.2 核心价值主张

| 价值点 | 说明 |
| --- | --- |
| **专业可信** | 回答引用真实法条并标注效力状态；引用校验机制降低模型幻觉；免责声明合规兜底 |
| **过程可视** | RAG 检索过程（子查询分解/检索统计）、多 Agent 执行轨迹（各 Agent 耗时与推理方式）全链路可视化 |
| **数据安全** | 业务数据按创建者归属、角色分层数据范围、越权访问拦截并告警留痕 |
| **本地私有** | 模型推理、向量库、关系图谱全部本地化部署，业务数据不出内网 |
| **开箱即用** | Docker Compose 一键部署，内置种子知识库与演示账号，首次启动自动建索引 |
| **体验现代** | 亮/暗双主题（格式刷风格一键切换）、玻璃拟态设计、全站数据驱动动态渲染 |

## 三、核心技术亮点

### 3.1 GraphRAG 三路混合检索 + 精排（问答准确性的基石）

```
用户提问
  │
  ├─ ① 查询预处理：指代消解 → 查询重写 →（复杂问题）子查询分解
  │
  ├─ ② 三路混合召回（并发）
  │     ├── 稠密向量：ChromaDB HNSW 余弦相似度 Top-20
  │     ├── 稀疏关键词：BM25（rank_bm25，法律感知分块 512/64）
  │     └── 知识图谱：Neo4j 关联实体扩展（GraphRAG）
  │
  ├─ ③ RRF 倒数排序融合（k=60）→ 候选合并去重
  │
  ├─ ④ Cross-Encoder 精排：bge-reranker-v2-m3 → Top-5 上下文
  │
  ├─ ⑤ 上下文构建：[1][2]…引用编号拼装 → LLM 流式生成（SSE 逐字）
  │
  ├─ ⑥ Self-RAG 自评估：法条准确性 / 逻辑完整性 / 事实一致性
  │     三维打分，置信度 < 0.6 自动扩大召回重检索一次
  │
  └─ ⑦ 引用校验：回答中的《法律》第X条 与检索结果比对，
        未命中引用追加核实提示（幻觉防护）
```

**关键设计**：所有回答强制引用真实检索命中的法条并标注效力状态（有效/已废止），从机制上抑制"编造法条"。

### 3.2 多 Agent 对抗式合同审查（StateGraph 编排）

```
parse_doc（类型识别/当事方提取）
   → split_clauses（法律感知条款拆分）
      ├── 主审 Agent（法务视角）：规则引擎 16 条 + LLM 语义风险双引擎
      ├── 复核 Agent（合规视角）：规则复检主审结论 + 主审遗漏复扫
      └── 反方 Agent（业务视角）：弱势方立场逐条质疑（LLM）
            ↓
       debate 对抗辩论（主审必须逐一回应反方质疑）
            ↓ 条件路由
   [未共识] → arbitrate 仲裁裁决 → risk_score
   [共识]  ─────────────────────→ risk_score
            ↓
   suggestions 修改建议汇总（主审/复核/反方/仲裁 + 缺失条款）
            ↓
   perspectives 三视角独立推理（法务/合规/业务 并发真实 LLM 调用）
            ↓
   report_generate 结构化报告 + 多 Agent 执行轨迹
```

- **风险评分模型**：`Σ(严重度权重 高10/中5/低2) + 复核异议×5 + 主审遗漏×12 + 完整性缺失×30`，上限 100；≥60 高风险 / ≥30 中风险 / <30 低风险；
- **真实性保障**：每个 Agent 节点记录 LLM 真实调用标记与耗时，报告内以"多 Agent 执行轨迹"可视化（禁止占位造假）；
- **降级韧性**：任一 LLM 调用失败时按该视角的真实规则分析数据合成兜底意见，三方意见永不为"无"。

### 3.3 AI 修订版合同导出（修改痕迹可视化）

- 依据审查建议，**LLM 逐条款真实改写**（结果随报告缓存，重复导出秒回）；
- python-docx 渲染四类痕迹：**【AI新增】绿色高亮 / 【AI修改】黄色高亮 + 红色删除线字符级 diff / 【AI删除】红色删除线**，文末附"AI 修改痕迹清单"总表；
- 中日韩字体显式设置（ascii/hAnsi/eastAsia 三属性），Word / WPS 双端渲染无缺字。

### 3.4 SSE 真流式 + 纯文本输出保障

- Ollama `stream=True` → FastAPI StreamingResponse → Nginx `proxy_buffering off` → 前端 fetch Reader，**token 级逐字渲染**（打字光标跟随）；
- 自研 `MarkdownStripper` 有状态流式清洗器：hold-back 缓冲解决"**/### 被网络分片切碎"的跨包标记问题，用户看到的每一字都是纯文本；
- 回复对象 `reactive` 化并先于流式请求入列，杜绝"等待后整段一次性出现"。

### 3.5 MCP（Model Context Protocol）工具生态

- 内置 8 个法律领域工具：法条检索 / 案例检索 / 合同模板获取 / 条款合规校验 / 经济补偿金计算 / 利息计算 / 合规要点检查 / 图谱查询；
- 工具 JSON Schema **动态驱动**参数表单渲染；支持启停、实时调用、健康检查、调用统计；
- 审计留痕每一次工具调用。

### 3.6 工程化特性

| 特性 | 实现 |
| --- | --- |
| 亮/暗双主题 | 全站语义化 CSS 变量 + Element Plus 双模式变量 + 格式刷风格切换控件 + localStorage 持久化 + ECharts 主题重绘 |
| 数据驱动动态渲染 | 业务字典中心（config 单一来源）经 `/api/meta/dictionaries` 下发，前端选项/标签零硬编码 |
| 数据变化自动上屏 | `useAutoRefresh` 组合式函数：定时轮询 + 窗口聚焦补刷 + 节流 + 快照比对防图表闪烁 |
| 多进程索引一致性 | Chroma 集合句柄失效自愈 + Redis Pub/Sub 广播触发各 worker 重建 BM25 |
| 统计口径对齐 | 仪表盘/列表/图表同源统计，口径差异在界面明示（"已完成 X / 全部 Y"） |

## 四、功能模块详解

> 各模块的界面截图与配套说明文案见[第五章](#五关键功能截图说明)。

### 4.1 认证与用户管理

- JWT（HS256，默认 12h）无状态认证；PBKDF2 12 万次迭代哈希存储；
- 登录防爆破：Redis 计数，5 次失败锁定 10 分钟；
- 登录返回**按角色过滤的菜单树**，前端据此渲染导航（RBAC 第一层）；
- 前端路由守卫二次校验角色等级，后端接口级 `require_module` 三重防护；
- 管理员可调整用户角色 / 启停账号 / 重置密码（二次确认 + 审计留痕）。

### 4.2 智能法律问答

- 多会话管理：创建/切换/删除，多轮上下文（最近 6 轮指代消解）；
- SSE 事件协议：`meta`（子查询/检索统计）→ `citation×N`（引用卡片先于答案推送）→ `token×N`（逐字输出）→ `confidence` → `done` → `session`；
- 回答展示：纯文本 + 引用法条卡片（法律名/条文号/效力/相关度）+ 置信度徽标 + 耗时；
- 快捷提问由**真实高频咨询数据**驱动（后端从提问记录提取，空库回退默认项）。

### 4.3 智能合同审查

- 双入口：粘贴文本（同步等待）或上传 docx/pdf/txt/md（异步受理 + 轮询）；
- 审查中展示七阶段进度动画（条款拆分 → 三视角推理 → 主审 → 复核 → 辩论 → 仲裁 → 报告）；
- 报告全可视化：概览指标 / 三视角审查意见（法务·合规·业务，标注 AI 推理来源）/ 风险清单 / 修改建议 / 对抗辩论推理链 / 多 Agent 执行轨迹，**不向用户暴露任何原始 JSON**；
- 审查记录分页管理，状态（审查中/已完成/失败）自动刷新上屏。

### 4.4 AI 修订版合同导出

- 记录列表与【查看报告】并列的【导出AI修改】按钮；
- 首次导出触发 LLM 逐条款改写（约 10-40s，结果缓存），生成 Word 下载；
- 修改痕迹四类标记 + 痕迹清单表，原文与 AI 改动一眼可辨。

### 4.5 知识库管理

- 四类文档 CRUD（法律法规/裁判案例/司法解释/合同模板），类型字典后端下发；
- 保存后自动执行：法律感知分块 → 向量入库 + BM25 同步 + 图谱写写（三路索引一致）；
- 全量重建（模型切换/数据修复）、索引规模统计（向量/BM25/图谱节点与关系）、文档详情查看；
- 多进程部署下索引变更经 Redis 广播同步至全部 worker。

### 4.6 数据分析

| 分析项 | 内容 | 数据范围 |
| --- | --- | --- |
| 咨询热点 | 业务领域分布饼图 / 日咨询量趋势 / 热点关键词词云 | 管理员=全平台；法务/用户=本人 |
| 法条引用 | 高频引用法条 Top20 柱图 / 法条共引关系网络（力导向图） | 同上 |
| 用户聚类 | K-Means 按行为特征分群（咨询/审查/置信度/活跃/角色五维） | 仅管理员（系统级功能） |

- 支持近 7/30/90 天周期切换；tab 切换自动重绘；数据变化自动刷新（快照比对防闪烁）。

### 4.7 仪表盘

- 六宫格核心指标 + 风险分布饼图 + 知识库构成玫瑰图 + 最近审查记录分页表；
- **角色感知数据范围**：管理员=全平台汇总（合同审查记录总数/咨询总数），法务/普通用户=仅本人数据；
- 30 秒自动刷新 + 窗口聚焦补刷，数据未变化不重绘（防闪烁）。

### 4.8 MCP 工具中心 / 4.9 审计日志 / 4.10 个人中心

- **MCP 工具中心**（管理员）：工具卡片墙 + 启停开关 + Schema 驱动调用器 + 执行结果 JSON + 健康检查；
- **审计日志**（管理员）：登录/问答/审查/上传/删除/导出等全操作留痕，支持模块/行为/时间范围过滤，15 秒自动上屏；
- **个人中心**：资料维护、密码修改（旧密码校验 + 两次确认）、当前角色权限说明。

### 4.11 主题与体验

- 顶栏格式刷风格切换控件（日/月滑块动画，登录页右上角同样提供）；
- 主题选择持久化（`zft_theme`），刷新/重登录保留；与业务登录态（`zft_auth`）隔离；

## 六、权限与数据安全模型

### 6.1 三角色权限与数据范围矩阵

| 功能 | 管理员 | 法务负责人 | 普通用户 |
| --- | --- | --- | --- |
| 仪表盘 | **全平台汇总**（合同审查记录总数/咨询总数） | 仅本人数据 | 仅本人数据 |
| 智能问答 | 仅本人会话 | 仅本人会话 | 仅本人会话 |
| 合同审查记录 | **查看全部角色记录**；删除仅限本人 | 仅本人 | 仅本人 |
| 知识库管理 | ✅ 管理 | ✅ 管理 | ❌ **禁止访问**（403） |
| 数据分析 | **全平台汇总** + 用户聚类 | 仅本人数据 | 仅本人数据 |
| MCP 工具 / 用户管理 / 审计日志 | ✅ | ❌ | ❌ |
| 个人中心 | ✅ 本人 | ✅ 本人 | ✅ 本人 |

### 6.2 数据安全机制

| 机制 | 说明 |
| --- | --- |
| 数据归属绑定 | 合同/会话/消息/引用落库即绑定创建者 `user_id` |
| 越权拒绝 | 非本人业务数据：读/删/导出返回 403 并记录 WARNING 告警日志；不存在返回 404（不泄露存在性） |
| 接口级鉴权 | `require_module` 按角色模块白名单校验，与菜单树同源 |
| 前端二次防护 | 路由守卫角色等级校验；越权页面不渲染（如聚类 tab 仅管理员可见） |
| 操作留痕 | 全业务操作（含导出、越权尝试）写入审计日志，不可抵赖 |
| 传输与存储 | JWT Bearer 认证；密码 PBKDF2-120k 哈希；数据库 utf8mb4 |

### 7.2 健康检查与自愈

| 服务 | 健康检查 | 自愈能力 |
| --- | --- | --- |
| 前端 | Nginx 127.0.0.1 探活 | restart: unless-stopped |
| 后端 | `/health` 五项依赖检查（mysql/redis/ollama/rerank/neo4j） | 双 worker；向量集合句柄失效自愈；统计接口逐项容错永不 500 |

### 7.3 运维要点

- **索引一致性**：知识库增删改后 Redis 广播，各 worker 自动重建 BM25；Chroma 集合句柄失效自动重挂载；
- **首次启动**：自动执行建表 SQL、导入种子知识、构建三路索引、初始化内置账号；
- **模型切换**：修改 `docker-compose.yml` 中 `LLM_MODEL`/`EMBEDDING_MODEL` 后重建后端，向量维度变更自动检测并重建索引；
- **历史数据修复**：启动时幂等修复 latin-1 误码的列默认值与行数据（合同标题/类型）。

## 八、质量保障与测试结论

- **测试体系**：自动化接口测试（10 大类 31 断言）+ 本地冒烟（25 项）+ 浏览器端到端 UX 测试 + 三角色渗透测试；

- **当前结论**：功能完整性、数据隔离、双主题对比度、性能基线（轻接口 ~15ms）全部达标，可用于生产交付。
